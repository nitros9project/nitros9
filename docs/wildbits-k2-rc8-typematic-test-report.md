## What changed

Three coordinated changes, tested together:

1. **Hardware typematic engine (FPGA core rc8, K2-only).** Key repeat is now
   generated by the optical-keyboard scanner in the core: while a key is held,
   the scanner re-pushes the matrix snapshot into the keyboard FIFO on a
   frame-counted schedule. New CPU registers: `$FE14` initial delay (frames,
   reset 30 = 500ms), `$FE15` repeat period (frames, reset 5 = 12 cps),
   `$FE16` bit 0 enable (reset 0 = **off** — older disks see stock behavior).
   Timing is counted in 60Hz video frames, making repeat speed independent of
   CPU clock (stock vs. turbo).

2. **Dual-mode keyboard driver (keydrv_k2).** At Init the driver probes $FE14
   with a write-then-readback. On an rc8+ core it arms the engine and lets the
   hardware pace repeats; on any older core the probe fails and the proven
   software repeat runs unchanged. One disk supports both cores.

3. **Interrupt-controller hygiene (krn + clock).** The FPGA interrupt
   controller's registers survive software reboots. Kernel cold start now
   masks and clears **all four** interrupt groups with absolute stores
   (before any driver installs), closing the inherited-interrupt storm window
   (e.g. WiFi bits left unmasked by `wizi` surviving into the next session).
   Clock Init was reduced to touching only its own SOF bit so it can never
   disturb another driver's arming. krn verified at exactly 4,096 bytes.

Core build quality: timing hold-clean (WHS +0.067), setup closed except the
known-benign 24→6MHz synchronizer CDC. Disk gates: bootfile 32,000 bytes
(≤ 32,256 ceiling), Krn final module, hardened DriveWire (divisor-5) and
WizFi $E1BEA2 aboard; all changes byte-verified present in the bootfile.

## Compatibility matrix (by design, probe-verified)

| Disk | Core | Behavior |
|------|------|----------|
| new  | rc8  | hardware-paced repeat (engine armed at boot) |
| new  | ≤rc7 | software repeat, byte-identical to previous behavior |
| old  | rc8  | stock behavior (engine resets disabled) |
| old  | ≤rc7 | baseline |

One operational rule: after running the new disk on rc8, use `wbreset` (or
power cycle) before booting a pre-typematic disk — the $FE16 enable survives
software reboots and the old driver doesn't know about it.

## Addendum: Phase 3 — interrupt-driven keyboard (same day, FIELD-VERIFIED)

Following typematic verification, the keyboard was moved off the 60Hz
clock tick onto its own hardware interrupt (group 3 bit 2 — the FIFO
empty→non-empty edge, wired in every core but never before serviced by
the OS). keydrv installs an F$IRQ handler at Init (unique-U registration
alongside mousedrv's existing entry; clear-pending-then-drain-to-empty
service discipline; RMW-only on the register shared with WiFi; graceful
fallback to tick polling if the install fails); the tick path remains as
a safety net. Keystroke service latency drops from up-to-16ms to
immediate. Deployed as `l2_wildbitsk2_p3.dsk`.

| Test | Result |
|------|--------|
| Boot + keyboard via interrupt | **PASS** |
| Typing latency / repeat feel | **PASS** — crisp, repeat unchanged |
| Mouse (F$IRQ table coexistence) | **PASS** |
| Held key during `format /f1` | **PASS** — drain-to-empty after masked stretches |
| `wbreset` cycle (handler + unmask re-arm) | **PASS** |
| Held key + WiFi telnet traffic soak | **PASS** — both drivers claiming edges off the shared INT_PENDING_3, no wedge |

**Phase 3: 6 of 6 passed, 0 failures.**
